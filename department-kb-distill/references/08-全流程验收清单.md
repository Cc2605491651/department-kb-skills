# 全流程验收清单

本清单用于新知识库蒸馏的阶段验收。所有统计必须能够追溯到源节点、稳定 ID、处理日志和本地输出文件。

## 一、启动验收

- [ ] 已填写知识库名称、空间 ID、空间链接和部门名称。
- [ ] 已确定蒸馏范围、排除范围和盘点快照时间。
- [ ] 已确定本地工作目录，并确认本轮是否只做本地处理。
- [ ] 已指定知识库负责人、业务确认人和权限负责人。
- [ ] 已准备业务分类和敏感内容范围；Owner固定取原文创建者，不使用映射表。
- [ ] 未将账号、Token、Cookie、个人路径等写入公开规范。

## 二、源库盘点验收

- [ ] 已递归获取全部目录和文件节点。
- [ ] 每个节点均记录 nodeId、父节点、标题、类型、链接、创建者和更新时间。
- [ ] 已区分Raw准入材料、经标准排除材料和待准入处理材料。
- [ ] 已记录无权限、空文件、异常节点和待补充信息。
- [ ] 满足：`源节点总数 = 可处理节点 + 明确排除节点 + 失败节点`。

## 三、下载与解析验收

- [ ] 每份附件下载后均校验文件存在、大小和实际格式。
- [ ] 在线文档已保存完整正文或可审计的 Raw Mirror。
- [ ] DOCX、可检索PDF、含文字PPTX、XLSX/钉钉表格、CSV、MD和TXT按对应策略处理。
- [ ] 独立图片、音频、视频和压缩包已进入标准排除清单，没有送入解析和Codex处理。
- [ ] 首次失败的文档已进行第二策略重试。
- [ ] 二次失败已进入失败清单，包含原因、证据和建议动作。
- [ ] 没有静默跳过任何源文件。

## 四、元数据与语义验收

- [ ] 每份成功文档均生成稳定 ID 和内容哈希。
- [ ] 每份成功文档均包含完整 17 字段，字段名和顺序统一。
- [ ] 每份成功文档页首都有固定版本统一AI检索元数据，两套视图除`view`外一致。
- [ ] 固定17字段和主题、业务对象、文档角色、输入、动作、产出、约束均已进入同一YAML区块，页面没有重复的旧区块。
- [ ] 摘要能说明文档解决什么问题、适用对象和关键结论。
- [ ] 类型、场景、关键词、状态和版本有正文或源元数据依据。
- [ ] 每份成功文档的Owner已经通过钉钉创建者UID和通讯录取得姓名；仍为“待补充”的文档已阻断整批确认。
- [ ] 不确定信息明确标记为“待确认”，未把推断写成事实。
- [ ] 长文档已按章节处理，并保留完整原文入口。
- [ ] Original Content和结果清单中已清除附件临时签名参数，未出现`Signature`、`AccessKeyId`、`Expires`或安全Token。

## 五、双目录页面验收

- [ ] 原目录镜像按源库目录层级生成。
- [ ] 业务知识目录按业务分类生成。
- [ ] 两个目录中的每份成功文档都是完整蒸馏页，不是简略占位页。
- [ ] 两个视图中同一文档的稳定 ID、17 字段、Raw Mirror、相关知识和原文一致。
- [ ] 页面内来源链接、Raw Mirror 和关联文档链接均可点击。
- [ ] 附件型文档提供原附件或完整可审计原文入口。
- [ ] 两套视图每一层文件夹均有可打开的`目录索引.md`。

## 六、关系验收

- [ ] 已先运行本地 R01—R10 候选规则，再由 Codex 阅读双方正文核验。
- [ ] 每条成立关系均记录双方稳定 ID、关系类型、证据、通俗解释和审核等级。
- [ ] “相关知识”明确说明关联文档名称、关系含义和可点击链接。
- [ ] L2 关系已自动通过并进入抽样清单。
- [ ] L3 关系已进入业务确认清单，未在确认前作为正式关系发布。
- [ ] 权限不对称的关联不会向低权限用户泄露标题、摘要或正文。

## 七、业务审核验收

- [ ] 待确认清单只保留业务负责人需要判断的内容。
- [ ] 每项包含两份文档名称、创建者、原文链接、关系解释和确认动作。
- [ ] 证据为原文真实段落，能够在原文中定位。
- [ ] 业务负责人可以选择确认、驳回、修订、失效或保留历史。
- [ ] 审核结论已写回关系台账和对应蒸馏页。

## 八、本地交付验收

- [ ] 已生成处理概况、文档清单、失败清单、关系总览和业务确认清单。
- [ ] 已生成可人工浏览的审核入口页。
- [ ] 已生成`00-AI问答与检索入口`、轻量AI知识库地图，没有巨大全量索引。
- [ ] 已生成`00-蒸馏结果与下一步`、逐文档处理结果矩阵和待办动作清单。
- [ ] 本地 Markdown 链接使用正确的相对路径或可访问绝对路径。
- [ ] 文件夹和文件名使用中文，必要时用括号解释技术名称。
- [ ] 已扫描并清除真实空间 ID、真实节点 ID、内部链接、个人路径和凭证。
- [ ] 在“仅本地”任务中，没有执行线上创建、修改、发布或归档操作。

## 九、发布与回读验收

仅在任务启动配置已提供最终写回文件夹链接并启用 `publishing` 后执行。

- [ ] 目标知识库、目标目录和发布范围已经确认。
- [ ] L3 关系均已确认或从发布内容中移除。
- [ ] 已按发布清单逐项写入，未上传本地日志、缓存、凭证或失败中间件。
- [ ] `task-config.yaml` 中的最终写回链接、发布根目录名和两套视图范围已经确认，CLI目标与配置一致。
- [ ] 删除、移动、改权限、覆盖非本程序节点均保持禁止。
- [ ] 本地相对链接已根据远程节点映射改写，正式页面不存在指向本地Markdown的Raw Mirror或关联链接。
- [ ] 发布分片不超过9,000字符，未切断代码块或表格；Unicode清洗有台账可追溯。
- [ ] 发布后通过 DWS 回读标题、17 字段、正文、链接和关系。
- [ ] 已回读每份页首统一AI检索元数据、根目录AI问答入口、知识库地图和目录索引。
- [ ] 已验证目录层级、访问权限和关联链接。
- [ ] 已遍历远程发布根目录，文件夹数、文档数和节点映射无缺失、无多余。
- [ ] 发布清单、回读结果和版本信息已归档。
- [ ] 回读后已刷新本地结果矩阵和待办动作清单。

## 十、最终通过条件

同时满足以下条件才可判定本批处理闭环：

```text
源文件总数 = 蒸馏成功数 + 明确失败数 + 经批准排除数
待处理数 = 0
静默遗漏数 = 0
成功文档缺少17字段数 = 0
成功文档缺少完整原文入口数 = 0
成功文档缺少创建者姓名数 = 0
未处置L3关系数 = 0（发布场景）
发布后回读失败数 = 0（发布场景）
```

若“明确失败数”大于 0，最终状态必须写“处理已闭环，仍有明确失败”，并附失败清单；只有明确失败数为 0 时，才可写“全量蒸馏全部成功”。

本地验收通过不自动把`status`改为“正式”。只有本次任务执行审核人在AI对话框明确确认整批蒸馏无误，才写入带内容哈希的确认记录并完成“候选→正式”状态变更。
