# 名词解释与规则对照

本文件统一蒸馏过程中使用的名词。执行规范、审核清单和蒸馏页面应优先使用这里的定义，避免自行创造难以理解的缩写。

## 一、核心名词

| 名词 | 通俗解释 | 用途 |
|---|---|---|
| 知识库蒸馏 | 把源知识库完整读取后，补充统一元数据、摘要、关系和可检索结构 | 建设可管理、可问答的新知识库 |
| 模型蒸馏 | 用大模型训练另一个更小模型 | 与本规范无关 |
| 源节点 | 源知识库中的一个目录、在线文档或附件 | 盘点和追溯的最小对象 |
| Raw Mirror（完整原文镜像） | 原文的本地完整副本或可审计读取结果 | 核对蒸馏内容是否忠于原文 |
| Original Content（完整原文） | 在蒸馏页中展示或连接到的完整正文、附件内容 | 用户直接阅读和 Codex 深读 |
| 原目录镜像 | 按源知识库目录层级组织的完整蒸馏页视图 | 保留原有找文档习惯 |
| 业务知识目录 | 按业务主题重新组织的完整蒸馏页视图 | 支持按业务场景找知识 |
| 双目录 | 原目录镜像和业务知识目录 | 同一内容的两种入口，不是两份独立事实 |
| 稳定 ID | 由空间和源节点身份计算的长期唯一编号 | 去重、关联、更新和迁移 |
| 内容哈希 | 对当前正文或附件内容计算的 SHA-256 | 判断内容是否完全相同或发生变化 |
| 17 字段 | 每份成功文档都要有的统一属性集合 | 检索、筛选、治理和问答 |
| 语义画像 | Codex 从正文提取的摘要、关键词、场景、对象、输入输出等内容特征 | 分类、关系判断和问答 |
| Owner | 钉钉原文创建者姓名 | 目录接口缺失时按nodeId搜索取得创建者UID，再查通讯录取得姓名；仍不可得才写待补充，不从正文猜测 |
| 来源更新时间 | 源知识库记录的最后更新时间 | 增量更新判断依据之一 |
| 处理状态 | 蒸馏流程状态，如已提取、待确认、已确认、失败 | 流程跟踪，不代表业务有效性 |
| 业务状态 | 蒸馏页是否已经完成整批验收；本规范使用候选、正式、已失效、待确认 | 判断能否作为当前已确认知识使用 |
| 候选 | 已成功蒸馏，但本次任务执行审核人尚未明确确认整批无误 | 可以审核和检索，不能当作已验收正式知识 |
| 正式 | 执行审核人已在AI对话框明确确认，且当前内容哈希与确认记录一致 | 可作为当前已验收知识；内容变化后自动回到候选 |

## 二、关系名词

| 名词 | 通俗解释 | 是否能直接展示 |
|---|---|---|
| 关系候选 | 规则或检索发现“可能有关”的两份文档 | 不能直接当作正式关系 |
| 已确认关系 | 已阅读双方正文，有足够证据支持的关系 | 可以，仍需遵守权限 |
| 明确引用 | 一份文档直接点名、链接或引用另一份文档 | 一般属于 L2；有风险时升为 L3 |
| 制度依据 | 流程、方案或通知明确以某制度作为规则来源 | 无冲突时可展示 |
| 版本关系 | 新旧版、替代、废止、修订或历史沿革 | 状态不明时需 L3 确认 |
| 上下游关系 | A 的输出会成为 B 的输入 | 需说明输入、输出具体是什么 |
| 实施关系 | 制度、流程、模板和案例围绕同一业务对象配套使用 | 需说明各自作用 |
| 同主题 | 内容相似但没有足够证据证明正式依赖 | 只能作为检索提示，不等于正式关系 |
| 冲突 | 两份文档对同一事项给出不能同时成立的规则或结论 | 必须 L3 确认 |
| 废止 | 文档已被正式停止使用 | 必须有明确证据或业务确认 |
| 制度效力 | 多份规则不一致时，哪份有权作为当前正式依据 | 无法从原文判断时必须 L3 确认 |
| 权限风险 | 关系展示可能让低权限用户知道无权查看的内容 | 必须由权限负责人处理 |
| 关系证据 | 能在双方原文中定位的标题、链接、编号或完整段落 | 用于审核和追溯 |
| 通俗解释 | 不使用内部缩写说明两份文档为什么有关、怎样一起使用 | 必须写入“相关知识” |

## 三、审核等级

| 等级 | 含义 | 处理方式 |
|---|---|---|
| L0 | 机器可确定、不依赖语义猜测，如完整内容哈希一致 | 自动通过 |
| L1 | 正文直接点名或链接另一文档，且 Codex 核对上下文一致 | 自动通过并抽样复核 |
| L2 | 双方正文证据充分、方向明确、无冲突和权限风险 | 自动通过，业务负责人抽样检查 |
| L3 | 涉及冲突、废止、制度效力、权限或重大业务口径 | 业务负责人确认后才可发布 |

等级表示审核风险，不表示关系强弱。即使是“明确引用”，只要同时存在冲突或权限风险，也必须升为 L3。

## 四、本地规则 R01—R10

| 编号 | 规则 | 判断方法 | 结果用途 |
|---|---|---|---|
| R01 | 完全重复 | 两份内容 SHA-256 一致 | 可自动确认重复 |
| R02 | 直接链接 | A 正文包含 B 的源链接或稳定链接 | 明确引用候选 |
| R03 | 稳定 ID | A 正文出现 B 的稳定 ID | 明确引用候选 |
| R04 | 标题引用 | “依据《某文档》”等表达匹配到标题 | 制度依据或引用候选 |
| R05 | 版本表达 | 标题主体相同，并出现新版、替代、废止、修订等词 | 版本关系候选 |
| R06 | 相同业务编号 | 项目号、工单号、制度编号等相同 | 同一业务对象候选 |
| R07 | 输入输出匹配 | A 的明确产出与 B 的明确输入相同 | 上下游关系候选 |
| R08 | 类型互补 | 同一业务对象下出现制度、流程、模板、案例等组合 | 实施关系候选 |
| R09 | 文本检索相似 | BM25 或 TF-IDF 排名靠前 | 低优先级同主题候选 |
| R10 | 路径上下文 | 位于同一项目或专题目录 | 仅作辅助证据，不能单独成立 |

R01—R10 的作用是缩小需要阅读的文档对，不代替 Codex 的正文核验。除 R01 的完全重复外，不应仅凭单条规则直接断言正式关系。

## 五、工具与流程名词

| 名词 | 通俗解释 |
|---|---|
| DWS | 读取和操作钉钉知识库、文档、云盘等数据的工具层 |
| Codex | 阅读文档、生成摘要、判断关系、执行规则并回答问题的智能执行层 |
| 统一AI检索元数据 | 每份知识页页首的一个结构化YAML区块，合并固定17字段和蒸馏画像，用于Agent先筛候选，不代替完整原文 |
| AI知识库地图 | 根目录的轻量业务导航，不罗列全量文档 |
| 目录索引 | 某一层文件夹的子目录和直接文档清单，用于浏览或搜索备用 |
| ACL（访问权限） | 决定谁可以看、读或修改某份文档的权限规则 |
| 发布门槛 | 正式写入线上知识库前必须满足的条件，也可称发布门禁 |
| 回读 | 发布后重新从线上读取，确认实际结果与本地内容一致 |
| 最终写回目录授权 | 任务启动时在 `task-config.yaml` 填写最终钉钉文件夹链接并启用 `publishing`；只授权本任务在该目录新建和更新本程序创建的节点，不授权删除、移动、改权限或覆盖既有节点 |
| 远程节点映射 | 本地页面路径与钉钉文档 nodeId 的对照表，用于改写Raw Mirror、索引和关联链接 |
| 安全分片 | 在钉钉单次写入限制内，按完整段落、表格和代码块边界拆分长文档 |
| 危险Unicode字符 | 文本中不可见且会被DWS安全校验拒绝的控制/格式字符；发布副本可移除，但必须记录码点和数量 |
| 目录树回读 | 发布后递归列出远程目录，确认文件夹和文档节点无缺失、无多余 |
| 关系台账 | 统一记录文档对、关系、证据、等级和审核状态的结构化清单 |
| 失败清单 | 记录无法下载、解析或确认的文档及其处理建议 |
| 本地工作台 | 蒸馏过程中保存 Raw、解析结果、蒸馏页、日志和审核清单的目录 |
| 增量蒸馏 | 只处理新增、变化或受关系影响的文档 |

## 六、状态建议值

| 状态 | 含义 |
|---|---|
| `extracted` | 已读取并完成基础解析 |
| `distilled` | 已生成元数据、摘要和蒸馏页 |
| `pending_review` | 等待人工确认 |
| `confirmed` | 已完成必要确认 |
| `published` | 已发布到目标知识库 |
| `readback_verified` | 已回读并验证 |
| `failed` | 下载、解析或处理失败 |
| `excluded` | 经批准不纳入本轮蒸馏 |
