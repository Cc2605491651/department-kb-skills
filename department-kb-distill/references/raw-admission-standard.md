# Raw原始材料收集与入库标准-20260730

## 1. 目的与边界

本标准只规定哪些原始材料可以进入Raw收集区，以及材料完成入库需要满足什么条件。

本标准在材料被判定为“已准入、退回补充、拒绝入库或待权限确认”时结束，不规定入库后的加工、审核、发布和使用方式。材料通过本标准，只代表可以作为后续处理的原始输入，不代表已经成为正式业务知识。

## 2. 入库原则

1. 内容必须与公司业务、管理或工作交付有关。
2. 材料必须真实、完整、可追溯，不能只有无法核验的转述。
3. 实体内容必须进入指定Raw收集区，外部链接不能作为唯一内容。
4. 文件必须非空、未损坏、未加密，并能由知识库成员和DWS完整读取或下载。
5. 权限不得因入库而扩大；权限未确认的材料先进入受控位置，不进入普通Raw。
6. 创建者直接作为内容Owner，不要求提交人额外填写Owner或维护Owner映射表。
7. 员工不需要填写摘要、关键词、分类、文档关系、有效版本和审核等级。
8. 白名单之外的格式默认不入库，不能因为理论上可以OCR、转写或解压就视为正式支持。

## 3. 内容准入范围

### 3.1 应当入库

- 制度、政策、规则、业务口径和执行标准；
- 流程、SOP、操作指南和验收方法；
- 已形成结论、决定或行动项的会议纪要和评审记录；
- 项目方案、正式交付物、复盘和有复用价值的问题记录；
- 指标定义、统计口径、数据字典和字段说明；
- 有实际使用说明的模板、清单和示例；
- 常见问题、异常处理、成功案例和失败教训；
- 影响业务执行的工作交接、临时授权和协作边界；
- 对外承诺、合同执行要求及其他业务依据。

### 3.2 满足条件后入库


| 材料        | 准入条件                                |
| --------- | ----------------------------------- |
| 日报、周报、月报  | 包含可复用结论、业务变化或明确行动，不收集纯流水账           |
| 聊天或即时沟通   | 已整理成文字结论；不直接提交聊天截图作为知识正文            |
| 草稿        | 仍在使用，或具有必要的历史、决策证据价值，并在标题或正文中表明草稿状态 |
| 原始数据或业务表格 | 能说明用途、数据来源、字段含义、统计口径和更新时间           |
| 外部系统材料    | Raw内有可独立阅读的正文、快照或数据说明，外链只用于追溯       |
| 固定版式证据    | PDF本身可读取，并能说明其业务用途和来源               |


### 3.3 不进入普通Raw

- 纯通知、问候、临时沟通和无复用价值的消息；
- 空模板、空文件、测试文件和没有上下文的数据；
- 与工作无关的个人材料；
- 已知为同一来源的重复副本；
- 密码、Token、Cookie、密钥、私钥等凭证；
- 未经授权的薪酬、绩效、证件、健康及其他个人敏感信息；
- 无访问权限、来源不明、已经损坏或无法打开的材料；
- 只能通过外部链接访问、Raw内没有实体正文或附件的材料；
- 不符合第4章格式白名单的文件。

同一内容来自不同会议、项目、部门或时间点时，属于不同来源证据，可以分别入库；不得因为内容相似就拒绝真实来源证据。

## 4. 文件格式准入标准

### 4.1 允许入库的格式白名单


| 类型         | 允许格式           | 入库要求                          |
| ---------- | -------------- | ----------------------------- |
| 钉钉原生文字文档   | 钉钉文档、`adoc`    | 正文完整，DWS可以读取                  |
| Word       | `.docx`        | 正文、表格和必要配图可正常打开               |
| PDF        | `.pdf`         | 必须包含可读取文字；纯扫描、纯图片PDF不入库       |
| PowerPoint | `.pptx`        | 必须包含可读取的页面文字；只由截图或图片组成的PPT不入库 |
| Excel与钉钉表格 | `.xlsx`、`axls` | 必须说明用途、数据来源、字段含义、统计口径和更新时间    |
| 结构化文本      | `.csv`         | 编码正常，并满足表格材料的上下文要求            |
| 普通文本       | `.md`、`.txt`   | 编码正常、正文完整，不依赖外部脚本才能显示         |


`.doc`、`.ppt`、`.xls`等旧版Office格式，应先转换为`.docx`、`.pptx`、`.xlsx`再提交。

### 4.2 直接拒绝的格式


| 类型              | 常见扩展名                                                        | 处理要求                     |
| --------------- | ------------------------------------------------------------ | ------------------------ |
| 独立图片            | `.jpg`、`.jpeg`、`.png`、`.gif`、`.webp`、`.heic`、`.bmp`、`.tiff`等 | 整理为Word或钉钉文档，并补充可独立理解的文字 |
| 音频              | `.mp3`、`.wav`、`.m4a`、`.aac`、`.flac`等                         | 提供文字转写稿或会议纪要后再提交         |
| 视频              | `.mp4`、`.mov`、`.avi`、`.mkv`、`.webm`等                         | 提供操作说明、内容纪要或文字转写稿后再提交    |
| 压缩包             | `.zip`、`.rar`、`.7z`、`.tar`、`.gz`等                            | 先解压，按每个成员文件的格式分别提交       |
| 可执行程序和安装包       | `.exe`、`.dmg`、`.apk`等                                        | 不作为普通知识材料入库              |
| 网页、程序和配置文件      | `.html`、`.js`、`.py`、`.sql`、`.json`、`.xml`等                   | 整理成白名单格式的说明文档后提交         |
| 加密、带密码、损坏或零字节文件 | 不限扩展名                                                        | 解密、修复或重新导出后再提交           |


### 4.3 嵌入资源边界

- Word、PPT、PDF或钉钉文档中的配图可以随主文档保留，不作为独立Raw材料。
- 如果主文档的知识全部存在于图片中、正文没有可读取文字，则整份材料退回补充文字版。
- 独立图片、音视频和压缩包即使能够下载，也不能按“元数据画像”方式绕过准入标准。

## 5. 文件大小和可读取性

通用标准不写死单个文件的固定大小，因为钉钉和DWS限制可能变化。文件必须同时满足：

- 不超过提交时平台允许的上传上限；
- DWS能够完整读取正文或完整下载原附件；
- 文件能够在合理时间内打开，且没有缺页、截断或缺失工作表；
- 超出当前能力的材料由提交人按完整章节、工作表或业务对象拆分，并保留原始来源链接。

具体格式、大小、页数和工作表限制应记录在独立的“格式兼容矩阵”中，包含测试日期和工具版本；兼容矩阵变化不修改本标准的内容准入原则。

## 6. 来源、创建者与权限

每份准入材料至少能够自动取得或明确识别：

- 标题；
- 钉钉节点或原始来源链接；
- 创建者；
- 创建时间和最近更新时间；
- 所在目录；
- 文件格式；
- 当前访问权限。

规则如下：

- `Owner = 钉钉原文创建者`；
- 首次目录接口未返回创建者时，可通过同一workspace内文档搜索按nodeId补取creatorUid，再查通讯录取得姓名；确定性查询仍不可得时标记“待补充”，不得从正文人名推测；
- 谁发起AI任务，谁是本次入库检查执行人；该信息只进入执行记录，不要求员工填写；
- 权限不明确、DWS无权读取或目标成员无法访问时，状态为“待权限确认”，不得进入普通Raw；
- 敏感材料只能进入经过批准的受控位置。

## 7. 入库结果

Raw收集检查只使用以下结果：


| 结果    | 含义                           |
| ----- | ---------------------------- |
| 已准入   | 内容、格式、来源和权限均满足本标准，可以进入后续处理范围 |
| 退回补充  | 内容有价值，但缺少文字版、上下文、字段说明或来源信息   |
| 拒绝入库  | 内容或格式明确不符合标准                 |
| 待权限确认 | 材料可能符合要求，但访问范围尚未确认           |


拒绝和退回必须保留材料名称、来源链接、创建者、拒绝原因和建议补充方式。不得因为准入检查而删除原始材料。

## 8. 入库验收

一次Raw收集任务满足以下条件才算完成：

```text
提交材料总数 = 已准入数 + 退回补充数 + 拒绝入库数 + 待权限确认数
未登记材料数 = 0
白名单外格式进入已准入数 = 0
外链作为唯一内容数 = 0
```

Raw验收只检查本标准规定的内容、格式、来源和权限。
