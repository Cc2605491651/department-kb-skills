# 部门知识库全量蒸馏执行总规范

## 1. 目标

将每个来源文档转化为可追溯、可检索、可关联、可审核、可发布和可增量维护的知识页，同时完整保留来源事实和权限边界。

完成状态必须同时满足：

```text
盘点总数 = Raw准入数 + 经标准排除数 + 待准入处理数
Raw准入数 = 蒸馏成功数 + 两次尝试后仍失败数
待处理数 = 0
静默遗漏数 = 0
```

## 2. 强制边界

1. 默认只读盘点和本地生成；未获授权不得线上创建、更新、移动、删除或改权限。
2. 原文逐字保留；摘要、画像和关系解释不得替代原文。
3. 不从标题、目录或文件名臆测正文事实。
4. `Owner = 钉钉原文创建者姓名`；目录接口缺失时用文档搜索按nodeId补取creatorUid，再通过通讯录取得姓名。创建者、更新时间和权限只使用确定性来源，不交给模型猜测。
5. 独立图片、音频、视频和压缩包按Raw标准直接排除，不用元数据画像绕过准入规则。
6. 原目录视图与业务分类视图是同一份蒸馏知识的两种组织方式，不是“原文页”和“蒸馏页”的拆分。
7. 每个成功来源在两套目录中的页面均包含页首统一AI检索元数据（固定17字段与蒸馏画像）、Raw Mirror、相关知识和完整原文或原附件。
8. L2 在证据完整且无高风险时自动通过并事后抽样；L3 发布前逐条人工确认。
9. 发布后必须回读，回读失败即发布失败。
10. 审核记录归档与来源文档归档分开处理。

## 3. 标准执行阶段

### 阶段0：任务初始化

- 建立独立任务目录；
- 填写 `task-config.yaml`；
- 创建 `LOCAL_ONLY` 标记；
- 明确来源空间、处理范围、排除目录、权限身份、本次任务发起人和L3业务确认人；
- 读取《Raw原始材料收集与入库标准》并确认准入清单；
- 固定规范、Skill、DWS、Codex提示词和输出Schema版本。

### 阶段1：只读盘点与Raw准入复核

- 递归读取知识库目录和文件；
- 记录 workspace、node、路径、类型、创建/更新时间、创建者UID和来源链接；
- 生成稳定ID；
- 记录排除范围和盘点快照时间；
- 冻结本批次来源清单。
- 白名单外格式进入“经Raw入库标准排除清单”，不进入解析阶段。

### 阶段2：下载与解析

- 在线文档读取或导出；
- 原生附件下载后校验文件头、字节数和SHA-256；
- 按文件类型选择解析器；
- 首次失败后更换兼容方式重试一次；
- 第二次失败进入失败清单，不伪造正文。

### 阶段3：确定性元数据

本地程序生成并校验：稳定ID、标题、路径、链接、时间、创建者、格式、父子关系、内容哈希、解析状态、权限域和双页面映射。

### 阶段4：Codex语义处理

Codex阅读全文或明确的附件元数据，输出摘要、类型候选、场景、关键词、主题、业务对象、输入、动作、产出、约束、显式引用、版本信号、关系线索、证据位置和警告。

### 阶段5：生成两套完整页面

- 原目录视图：按来源相对路径组织；
- 业务分类视图：按部门业务场景组织；
- 两页使用相同稳定ID、17字段、关系和原文；
- 页首固定统一AI检索元数据，用于Agent低成本初筛，不取代原文；
- 只允许目录路径、交叉导航链接不同。

### 阶段6：关系候选召回

使用R01—R10进行候选召回。至少命中一条强证据或两条独立中证据才进入语义核验；R09、R10不能单独发布关系。

### 阶段7：Codex双端核验

Codex同时阅读双方画像和证据原文，输出成立/驳回、类型、方向、通俗含义、双方证据、风险和审核级别。

### 阶段8：审核

- L0/L1自动通过；
- L2自动通过并按固定比例抽样；
- L3进入负责人确认清单；
- 已驳回关系保留审计记录，内容未变化时不重复召回。

### 阶段9：本地交付与验收

生成`00-蒸馏结果与下一步`、逐文档结果矩阵和待办动作清单；验证总量闭合、页首统一AI检索元数据、双页面一致、原文完整性、关系门槛、权限、失败清单、链接和各层目录索引。

本次任务执行审核人在AI对话框明确确认整批蒸馏无误后，记录确认人、原话、时间和各文档内容哈希；哈希未变化的成功文档`status`由“候选”改为“正式”。AI不得自行确认，来源内容变化后该文档自动回到“候选”。

### 阶段10：发布、回读与归档

仅发布审核通过内容。任务启动时在 `task-config.yaml` 提供最终写回文件夹链接并启用 `publishing`，即构成本次任务的目标目录写入授权；无需额外授权JSON。先小批烟雾测试，再发布两套知识视图、根目录AI问答入口、轻量知识库地图和各层目录索引。单次Markdown不超过9,000字符，并发与批次均不超过30。线上回读页首统一AI检索元数据、原文、链接和目录树；成功后刷新结果矩阵并归档审核记录。

## 4. 增量维护

发生新增、内容变化、路径变化、权限变化、状态变化或规则版本变化时，按稳定ID识别来源并重算受影响页面和关系。任一关系端内容哈希、状态或权限变化时，已发布关系转为“待复审”。

## 5. 完成声明

只有在盘点总数、Raw准入、标准排除和解析结果全部闭合，语义处理、双页面验证及关系审核完成，所有失败均有记录和处置结论时，可以报告“本批处理已闭环”。只有Raw准入材料的失败数为0且线上回读全部成功时，才能报告“本批知识库蒸馏与发布全部成功”。仅本地任务不得报告“已发布”。
